# 通用约定

CurseForge 与 MC百科共用的条款，两个模块都遵守。

## 目录

- 沿用开发者现有目录约定（如 `<模组根目录>/<项目名>/<MC版本>-<加载器>-<模组名>`），不重命名已有项目。
- 临时文件、导出数据、中间脚本放项目内 `build/mcmod/`（或用户指定目录，不要把一次性脚本写进发布目录）。
- 给用户的定稿和提交脚本复制到项目 `docs/mcmod/upload/`；CF 项目资料放项目 `curseforge/` 目录。
- 文档里的脚本路径都相对本 skill 安装目录，需要绝对路径时用实际安装位置替换前缀。

## 版本与命名

- 发布版本名用 `Minecraft版本-加载器-模组名-版本号`。
- 要求「+0.1」时先去掉 `fix` 后缀再递增；JEI 附属模组追加实际兼容的最低 JEI 版本。
- 优先使用目标版本已有的正式 JAR；用户已提供且信息一致时不重复构建，也不擅自改版本号。已有产物与线上版本冲突时报告，不默默重编译替换。

## 事实来源优先级

1. 目标版本的源码、数据包、`neoforge.mods.toml` / `mods.toml` / `fabric.mod.json`、语言文件。
2. JAR 内元数据与代码（核对依赖兼容性与注册名时）。
3. 平台页面与 API（CF 项目页、文件页、Game Versions API；百科站内已有条目）。
4. 记忆与推测——不采用。

wiki 上已有的旧汉化、旧版本条目都不算数；未发布到线上的本地改动也不写进对外资料。

## 汇报格式

结束时给出：

- 生成或改动的文件路径、条目数、暂缓条目及原因。
- 与源码不一致、需要用户决定的地方（tooltip 与代码差异、重名、缺翻译）。
- 需要用户操作的事项，附具体链接和步骤。
- 平台返回的实际状态，不给「应该能过审」这类承诺。
