# 从项目导出数据

## 运行时导出

在项目 gametest 源集里写一个导出测试，把每个物品的类名、堆叠、耐久、稀有度、防火、属性修饰符（优先 `stack.getAttributeModifiers()`，取不到再回退默认值）、`appendHoverText` 结果、工具在各规则中的最大挖掘速度写成 JSON，然后跑 `gameTestServer`。

## 静态解析

配方（含模组自定义配方类型）、战利品表、世界生成、进度奖励、NPC 交易。

- 结构箱子来源要把战利品表映射到结构中文名：从 `worldgen/structure/*.json` 的 `start_pool` 出发，沿 `template_pool` 与 NBT 里的拼图引用找到全部部件，再在部件 NBT（gzip）中匹配 `chests/...` 战利品表。
- 结构名用 `structure.<modid>.<id>` 翻译键；缺翻译先补语言文件再写百科，不要写「部分结构」。
- 未被任何地方引用的战利品表不算来源。
- 获取方式还要查：代码注册的酿造配方（`RegisterBrewingRecipesEvent`）、方块战利品表（作物/果实/板条箱）、`mobInteract` 交互（挤奶、喂食）。只有导出文档里的配方和宝箱不够。

## 名称与一致性

- 名称一律取本地语言文件。
- 发现重名（两个物品英文名相同）或明显错译，先停下让用户决定改名，改名后再提交。
- tooltip 与代码不一致时以代码为准，并在汇报里列出差异。

## 方块批量提交前的额外检查

- 注册名后缀与名称是否一致（`_stairs` 要叫「楼梯 / Stairs」，`_slab` 要叫「台阶/半砖 / Slab」，`_wall` 要叫「墙 / Wall」），不一致的放进暂缓清单。
- 结构来源除了 `worldgen/structure` → 模板池，还要搜 Java 里直接 `getStructureManager().get(...)` 放置的结构（如固定坐标生成的特殊结构），以及凿子等工具在方块之间互相转换的来源。
- 没有配方、战利品、自然生成，也不在任何会生成的结构里的方块，生存模式无法获得，自动放进暂缓清单，不提交。
- 给用户的清单文档两列：中文名称 | 资料描述（【资料类型】+ 一句关键特性或主要获取方式），另附脚本与条目对应表、暂缓清单。

## 产物位置

导出 JSON、中间脚本放 `build/mcmod/`；给用户的定稿与提交脚本放 `docs/mcmod/upload/`。
